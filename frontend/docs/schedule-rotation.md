# Ротации, замена расписания и one-way рейсы

## Контекст

Замена расписания самолёта в полёте/на обороте раньше уничтожала все его будущие рейсы (включая обратное плечо текущей ротации): борт «телепортировался» в чужой аэропорт, расписание становилось пустым, активация блокировалась `AIRCRAFT_OUT_OF_POSITION`.

## Правила (источник истины — BFF `bff/src/modules/operations/`)

1. **Защита текущей ротации** (`aircraft-position.ts → rotationProtectedFlights`): при `PUT /operations/schedules` рейсы, которые уже вылетели/на посадке, и сцепленные с ними обратные плечи того же расписания (origin = destination предыдущего, вылет ≤ 24ч после прилёта) не удаляются. Новые рейсы генерируются только с вылетом **после** окончания ротации (`schedule-replace.ts → dropFlightsBeforeRotationEnd`, пары outbound+return отбрасываются атомарно).
2. **Позиция — предупреждение, не блокер** (`planning-checks.ts → addPositionWarning`): проверка идёт по *прогнозной* позиции (`projectedAircraftAirport` — куда борт прилетит после всех сохранённых рейсов). Расписание активируется всегда.
3. **Авто-отмена пропущенных вылетов** (`auto-cancel.ts`): при каждой загрузке снапшота операции рейс, чей вылет наступил, а борт физически не в аэропорту отправления, помечается `cancelled` (событие `FLIGHT_AUTO_CANCELLED`, severity warning). Каскад обрабатывается последовательной симуляцией позиции по каждому борту. Уже засеттлённые рейсы (`actual`/completed) ретроактивно не отменяются.
4. **One-way только между хабами** (`planning-checks.ts → addOneWayBlocker`, код `ONE_WAY_REQUIRES_HUBS`): `round_trip=false` допустим, только если origin и destination — хабы (база или купленные). `round_trip` задаётся пер-блоком в `PUT /operations/schedules` (`blocks[].round_trip`).
5. **Статусы рейсов производные**: stored `status` может отставать; перед фильтрацией/удалением всегда применяйте `currentFlightStatus`/`updateFlightStatuses` (это уже делают `replaceSchedules` и `deleteFutureFlightsForSchedules`).

## Frontend (apps/fleet-ops)

- В Schedule Builder есть чекбокс «В одну сторону (между хабами)» — действует на новые блоки выбранного hub-to-hub маршрута; one-way блоки рисуются одним плечом.
- **Анализатор готовности** (`schedule-readiness.ts → analyzeScheduleReadiness`): симулирует позицию борта по недельной сетке (две недели подряд для устойчивого состояния), подсвечивает красным блоки, к которым борт не успеет (они будут авто-отменены), и предупреждает, если сетка не возвращает борт в стартовый аэропорт.
